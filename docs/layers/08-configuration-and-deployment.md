# Configuration and deployment

This layer is everything that turns the `app/` modules into a running service: the twelve-field frozen `Settings` dataclass that every other layer's knob passes through, the `.env.example` template that documents each environment variable, the eight-line `Dockerfile` that builds the app image on uv's Python 3.12 base, the `docker-compose.yml` that brings up Neo4j and the app in one command, and the `pyproject.toml` / `uv.lock` pair that declares and pins dependencies and configures pytest. It has no logic of its own beyond reading `os.environ` once and coercing three numbers; validation of what was read happens downstream in `build_llm` and `Neo4jBrain`, at startup.

**Files:** `app/config.py`, `.env.example`, `Dockerfile`, `docker-compose.yml`, `pyproject.toml`, `uv.lock`

**Depends on:** nothing inside `app/` (`app/config.py` imports only `os` and `dataclasses`). **Used by:** [API layer](01-api-layer.md) (`create_app` calls `Settings.from_env()` and wires brain, LLM and `SessionStore` from it), [Orchestration and short-term context](02-orchestration-and-short-term-context.md) (`SessionStore(settings.recent_limit)`, `ChatService(..., settings.memory_limit, settings.min_confidence)`), [Shared Brain](05-shared-brain.md) (`Neo4jBrain(settings.neo4j_uri, settings.neo4j_user, settings.neo4j_password)`), [Memory update](06-memory-update.md) (`validate(candidates, min_confidence)`), [LLM providers](07-llm-providers.md) (`build_llm(settings)`), [Testing and verification](09-testing-and-verification.md) (`tests/conftest.py` constructs `Settings(...)` directly). Overview: [README](README.md).

## What this layer is

| File | What it contains | Size and shape |
|---|---|---|
| `app/config.py` | `Settings`, a `@dataclass(frozen=True)` with twelve fields and one classmethod `Settings.from_env()` | 36 lines, two imports (`os`, `dataclasses`), no imports from `app/` |
| `.env.example` | Every environment variable the service reads, grouped as Shared Brain, LLM, and Context budgets, each set to the code default with an inline comment | 19 non-blank lines |
| `Dockerfile` | A single-stage image: uv base, lockfile-first dependency layer, app source, uvicorn command | 8 instructions |
| `docker-compose.yml` | Two services (`neo4j`, `app`) and one named volume (`neo4j_data`) | 33 lines |
| `pyproject.toml` | Project metadata, five runtime dependencies, a `dev` dependency group of three, and `[tool.pytest.ini_options]`. No `[build-system]` table | 20 lines |
| `uv.lock` | The resolved dependency graph (`version = 1`, `requires-python = ">=3.12"`); `astrochat` is recorded as `source = { virtual = "." }` | 916 lines, generated by uv, committed |

Two variables the service reads are deliberately not fields of `Settings`:

- `LOG_LEVEL` is read by `logging.basicConfig(level=os.getenv("LOG_LEVEL", "INFO"), ...)` at the top of `app/main.py`, at import time, before `create_app` runs.
- `ANTHROPIC_API_KEY` is never read by our code. `AnthropicLLM.__init__` constructs `anthropic.AsyncAnthropic(**client_kwargs)` with no key argument; the SDK resolves it (the code comment: "key from ANTHROPIC_API_KEY or an `ant auth` profile").

`tests/test_neo4j.py` reads three more with `os.getenv`: `NEO4J_TEST_URI` (its presence enables the live test), `NEO4J_USER` and `NEO4J_PASSWORD`. These are test-only and go through `Neo4jBrain` directly, not through `Settings`.

## Why it exists

The requirements this layer answers are spread over several TDD sections and the README:

- **One place for every knob.** TDD §15 lists `config.py  # Settings from environment` as one of the eleven modules and names `README.md`, `pyproject.toml / uv.lock`, `.env.example`, `Dockerfile` and `docker-compose.yml # neo4j + app` as the only files outside `app/` and `tests/`. TDD §25 puts "Add config and dependency injection" in the first 25 minutes of the implementation window, before Neo4j. The context budgets in TDD §21 (recent messages <= 10, long-term memories <= 8) and the extraction threshold in README "Memory strategy" (`MIN_CONFIDENCE` 0.6) are the numeric fields.
- **Credentials out of source.** TDD §20: "Do not include credentials in source code. Store LLM/Neo4j credentials in environment variables or a secret manager." Every credential (`NEO4J_PASSWORD`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`) arrives through the environment; `.env` is listed in `.gitignore` under "Environments" so a filled-in copy of `.env.example` is never committed.
- **Structured observability.** TDD §19: "Log structured events, not full prompts by default", with a suggested field list. The `LOG_LEVEL` read and the record format in `app/main.py` are this layer's part of the answer; the one `log.info("chat ...")` line in `ChatService.chat` is what they format. See "Logging" below for which suggested fields are and are not present.
- **Runnable in one command.** TDD §23 Phase 1 (Assignment MVP) is "In-memory session store, Neo4j Shared Brain, One LLM provider, Rules + structured LLM memory extraction, Simple retrieval ranking, Automated tests". `docker compose up --build` (README "Run it") is that Phase 1 deployment: Neo4j and the app, wired, with the LLM chosen by exported variables.
- **Tests without services.** CLAUDE.md: "`main.py`: `create_app(brain=, llm=, settings=)` factory; tests inject fakes here." Because `Settings` is a plain dataclass, `tests/conftest.py` builds one with `Settings(brain="memory", llm_provider="mock")` and never touches the environment, which is what lets `uv run pytest` run in a few seconds with no Neo4j and no API key (README "Tests").
- **Provider independence by configuration.** TDD §27, row §10: "Not vendor-locked: the same service runs on OpenAI, a local Ollama, vLLM or a gateway by changing env vars." The provider switch (`LLM_PROVIDER`, `OPENAI_BASE_URL`, `LLM_MODEL`) is therefore configuration, not code.

## How it works

### `Settings`

```python
@dataclass(frozen=True)
class Settings:
    brain: str = "neo4j"  # neo4j | memory
    neo4j_uri: str = "bolt://localhost:7687"
    neo4j_user: str = "neo4j"
    neo4j_password: str = "password"
    llm_provider: str = "anthropic"  # anthropic | openai | mock
    llm_model: str = ""  # required for openai (server-specific names); anthropic falls back to claude-opus-5
    llm_effort: str = "medium"  # effort / reasoning_effort for both providers; empty omits it
    openai_base_url: str = ""  # any OpenAI-compatible endpoint; empty means api.openai.com
    openai_api_key: str = ""
    recent_limit: int = 10
    memory_limit: int = 8
    min_confidence: float = 0.6
```

| Field | Env var | Default | Coercion in `from_env` | Consumer (file, symbol) and what it does with the value |
|---|---|---|---|---|
| `brain` | `BRAIN` | `"neo4j"` | none (string passthrough) | `app/main.py` `create_app.lifespan`: `InMemoryBrain()` if the value is exactly `"memory"`, otherwise `Neo4jBrain(...)`. Any other string, including a typo, selects Neo4j |
| `neo4j_uri` | `NEO4J_URI` | `"bolt://localhost:7687"` | none | `app/brain.py` `Neo4jBrain.__init__` -> `AsyncGraphDatabase.driver(uri, ...)` |
| `neo4j_user` | `NEO4J_USER` | `"neo4j"` | none | `Neo4jBrain.__init__` -> `auth=(user, password)` |
| `neo4j_password` | `NEO4J_PASSWORD` | `"password"` | none | same |
| `llm_provider` | `LLM_PROVIDER` | `"anthropic"` | none | `app/llm.py` `build_llm`: `match` on the exact strings `"mock"`, `"anthropic"`, `"openai"`; anything else raises `ValueError` |
| `llm_model` | `LLM_MODEL` | `""` | none | `build_llm`: anthropic uses `settings.llm_model or "claude-opus-5"`; openai passes it to `OpenAICompatibleLLM.__init__`, which raises `ValueError` when empty; mock ignores it |
| `llm_effort` | `LLM_EFFORT` | `"medium"` | none | `AnthropicLLM.generate` sends `output_config={"effort": self._effort}`; `OpenAICompatibleLLM.__init__` builds `{"reasoning_effort": effort} if effort else {}` and sends it on both `generate` and `extract_memories` |
| `openai_base_url` | `OPENAI_BASE_URL` | `""` | none | `OpenAICompatibleLLM.__init__`: `base_url=base_url or None`, so empty means the SDK default (api.openai.com) |
| `openai_api_key` | `OPENAI_API_KEY` | `""` | none | `OpenAICompatibleLLM.__init__`: `api_key=api_key or "not-needed"` because the SDK insists on a non-empty key while local servers ignore it |
| `recent_limit` | `RECENT_LIMIT` | `10` | `int(...)` | `create_app.lifespan` -> `SessionStore(settings.recent_limit)` -> `deque(maxlen=limit)` per `(user_id, session_id)` in `app/session.py` |
| `memory_limit` | `MEMORY_LIMIT` | `8` | `int(...)` | `create_app.lifespan` -> `ChatService(..., memory_limit, ...)` -> `brain.search_memories(user_id, search, self.memory_limit)` -> Cypher `LIMIT $limit` in `SEARCH_MEMORIES` |
| `min_confidence` | `MIN_CONFIDENCE` | `0.6` | `float(...)` | `create_app.lifespan` -> `ChatService(..., min_confidence)` -> `memory.remember(..., self.min_confidence)` -> `memory.validate`, which drops candidates with `c.confidence < min_confidence` |

The table was checked against `dataclasses.fields(Settings)`; the twelve names, defaults and types above are what the class reports.

### `Settings.from_env()` walkthrough

```python
    @classmethod
    def from_env(cls) -> "Settings":
        env = os.environ.get
        return cls(
            brain=env("BRAIN", cls.brain),
            neo4j_uri=env("NEO4J_URI", cls.neo4j_uri),
            neo4j_user=env("NEO4J_USER", cls.neo4j_user),
            neo4j_password=env("NEO4J_PASSWORD", cls.neo4j_password),
            llm_provider=env("LLM_PROVIDER", cls.llm_provider),
            llm_model=env("LLM_MODEL", cls.llm_model),
            llm_effort=env("LLM_EFFORT", cls.llm_effort),
            openai_base_url=env("OPENAI_BASE_URL", cls.openai_base_url),
            openai_api_key=env("OPENAI_API_KEY", cls.openai_api_key),
            recent_limit=int(env("RECENT_LIMIT", cls.recent_limit)),
            memory_limit=int(env("MEMORY_LIMIT", cls.memory_limit)),
            min_confidence=float(env("MIN_CONFIDENCE", cls.min_confidence)),
        )
```

1. Every field is `env("NAME", cls.field)`: the class attribute is the fallback, so each default is declared once, on the field, and `from_env` cannot drift from `Settings()`.
2. The nine string fields pass through untouched: no `strip()`, no case folding, no membership check. `BRAIN=Memory` or `LLM_PROVIDER=Anthropic ` (trailing space) are therefore not the values the consumers compare against.
3. The three numeric fields wrap the lookup in `int()` or `float()`. When the variable is absent the default (already an `int` or `float`) round-trips through the constructor unchanged. When it is present but not parseable, including the empty string that `VAR=` produces, `from_env` raises `ValueError` (observed: `RECENT_LIMIT=abc` and `RECENT_LIMIT=` both fail with `invalid literal for int() with base 10`).
4. `from_env` is only called from `create_app` and only when no `settings` argument was given: `settings = settings or Settings.from_env()`.
5. The last line of `app/main.py` is `app = create_app()`, so the environment is read once, at import of `app.main`, which for `uvicorn app.main:app` is process start. Nothing in `app/` reads `os.environ` afterwards (the one other read, `LOG_LEVEL`, is also at import). Changing a variable means restarting the process.
6. A consequence worth knowing: `tests/conftest.py` imports `create_app` from `app.main`, which executes that module-level `app = create_app()` and therefore `Settings.from_env()` against the real shell environment. The module-level app's lifespan never runs under pytest, so no Neo4j driver or LLM client is built from it, but the numeric coercion does run: `RECENT_LIMIT=abc uv run pytest` fails at collection (observed). `LLM_PROVIDER=gemini` in the shell does not break the suite, because provider validation is deferred to lifespan (see next section).

### Startup: what `create_app` builds from `Settings`, in order

The `lifespan` closure in `create_app` (`app/main.py`) runs when uvicorn starts the ASGI app, or when `TestClient(app)` is entered as a context manager:

```python
        app.state.brain = brain or (
            InMemoryBrain() if settings.brain == "memory"
            else Neo4jBrain(settings.neo4j_uri, settings.neo4j_user, settings.neo4j_password))
        if isinstance(app.state.brain, Neo4jBrain):
            try:
                await app.state.brain.ensure_schema()
            except BrainUnavailable as e:
                log.warning("Neo4j unreachable at startup, serving degraded until it returns: %s", e)
        app.state.llm = llm or build_llm(settings)
        app.state.chat = ChatService(app.state.brain, app.state.llm, SessionStore(settings.recent_limit),
                                     settings.memory_limit, settings.min_confidence)
        log.info("ready brain=%s llm=%s", type(app.state.brain).__name__, type(app.state.llm).__name__)
```

1. **Brain.** An injected `brain` wins; otherwise `BRAIN` decides. Constructing `Neo4jBrain` creates a driver object and does not open a connection.
2. **Schema.** Only for `Neo4jBrain`: `ensure_schema()` runs the three statements in `SCHEMA` (two uniqueness constraints, one composite index). This is the first network call. `BrainUnavailable` is caught and logged; the process keeps starting. This is the only place `ensure_schema` is called, so if Neo4j is down at startup the constraints and index are not created for the life of that process (inferred from the code; the request path never retries schema creation).
3. **LLM.** An injected `llm` wins; otherwise `build_llm(settings)`. This is where `LLM_PROVIDER` and `LLM_MODEL` are validated. A `ValueError` here propagates out of `lifespan`; uvicorn prints the traceback followed by `ERROR: Application startup failed. Exiting.` (observed with `LLM_PROVIDER=gemini`).
4. **Orchestrator.** `ChatService` receives the brain, the LLM, a `SessionStore` sized by `recent_limit`, and the two remaining numbers. This is the only place `Settings` values are handed to the pipeline; `ChatService`, `SessionStore` and `Neo4jBrain` receive plain values, never the `Settings` object. Apart from `create_app` itself, the only function that takes the whole object is `build_llm`.
5. **Ready line.** `ready brain=Neo4jBrain llm=AnthropicLLM` (class names) is the one log line that records which provider the process is running.
6. **Shutdown.** `if close := getattr(app.state.brain, "close", None): await close()` closes the Neo4j driver; `InMemoryBrain` has no `close`.

### Provider-specific requirements

```python
def build_llm(settings: Settings) -> LLMProvider:
    match settings.llm_provider:
        case "mock":
            return MockLLM()
        case "anthropic":
            return AnthropicLLM(settings.llm_model or "claude-opus-5", settings.llm_effort)
        case "openai":
            return OpenAICompatibleLLM(settings.llm_model, settings.openai_base_url, settings.openai_api_key,
                                       settings.llm_effort)
    raise ValueError(f"unknown LLM_PROVIDER {settings.llm_provider!r}; use anthropic, openai or mock")
```

| `LLM_PROVIDER` | Required | `LLM_MODEL` | `LLM_EFFORT` | Credentials |
|---|---|---|---|---|
| `anthropic` (default) | `ANTHROPIC_API_KEY` in the environment, or an `ant auth` profile (code comment in `AnthropicLLM.__init__`) | optional; empty falls back to `claude-opus-5` (`settings.llm_model or "claude-opus-5"`) | forwarded as `output_config={"effort": ...}` on `messages.create` (generation). Not sent on `messages.parse` (extraction). `AnthropicLLM` always includes the key, so an empty `LLM_EFFORT` is sent as `""` rather than omitted; the empty-to-omit rule exists only in the OpenAI-compatible adapter (README "Configuration" says empty omits the parameter for both; the code omits it for `openai` only) | resolved by the SDK, not by `Settings`; `Settings` has no field for it. A missing key is not detected at startup: the client constructs, and the first request fails (see "Failure modes") |
| `openai` | `LLM_MODEL` (TDD §10: "required, since model names are server-specific"); `OpenAICompatibleLLM.__init__` raises `ValueError("LLM_MODEL is required for LLM_PROVIDER=openai (model names are server-specific)")` when it is empty | required | forwarded as `reasoning_effort` on both generation and extraction when non-empty; omitted when empty (for models that reject the parameter, per the code comment and TDD §10) | `OPENAI_BASE_URL`: empty means the SDK default, api.openai.com; set to e.g. `http://localhost:11434/v1` for Ollama. `OPENAI_API_KEY`: may be empty for local servers; the adapter substitutes `"not-needed"` because the SDK rejects an empty key |
| `mock` | nothing | ignored | ignored | none |

`.env.example` and README "Run it" list the servers the `openai` provider is meant for: OpenAI itself, Ollama, vLLM, Groq, OpenRouter, LM Studio, or a gateway.

### The two demo modes

- **`BRAIN=memory`** selects `InMemoryBrain`, the dict-backed implementation of the `SharedBrain` protocol. TDD §27 (row §4.4, §16) records why it exists as a first-class implementation: "Tests and no-Neo4j demo runs; it is also the executable reference for the Cypher semantics." State lives in the process and is lost on restart. `Neo4jBrain` is never constructed, so no driver, no schema call, no connect-timeout wait.
- **`LLM_PROVIDER=mock`** selects `MockLLM`: `generate` returns `(mock) Replying to '<message>' using context: <rendered context>` so the response shows what was injected, and `extract_memories` runs `extract_by_rules`, the regex extractor that covers the PRD example sentences. TDD §10: "Tests use it exclusively; it also serves as a no-key demo mode (`LLM_PROVIDER=mock`)."

Together they are README's "No Neo4j, no key" run: `BRAIN=memory LLM_PROVIDER=mock uv run uvicorn app.main:app`. Separately, `LLM_PROVIDER=mock` against a real Neo4j is what README's "The PRD conversation, end to end" transcript uses, so that `context_used` and `memory_updates` are the visible output rather than model prose.

### `.env.example` walkthrough and how to load it

```text
# Shared Brain
BRAIN=neo4j                  # neo4j | memory (in-process, for demos without Neo4j)
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=password

# LLM: pick one provider
LLM_PROVIDER=anthropic       # anthropic | openai | mock (deterministic, no key needed)
LLM_MODEL=                   # anthropic defaults to claude-opus-5; required for openai (server-specific, e.g. gpt-4o, llama3.1)
LLM_EFFORT=medium            # low | medium | high. anthropic: effort; openai: reasoning_effort. Empty = omit
```

The file has three groups. **Shared Brain** (`BRAIN`, `NEO4J_URI`, `NEO4J_USER`, `NEO4J_PASSWORD`) matches the first four `Settings` fields. **LLM** covers `LLM_PROVIDER`, `LLM_MODEL`, `LLM_EFFORT`, then `ANTHROPIC_API_KEY`, then `OPENAI_BASE_URL` and `OPENAI_API_KEY` with a comment naming the compatible servers and noting the key may stay empty for local ones. **Context budgets** holds `RECENT_LIMIT`, `MEMORY_LIMIT`, `MIN_CONFIDENCE` and, in the same block, `LOG_LEVEL=INFO`. Every value in the file equals the code default: loading it unchanged and calling `Settings.from_env()` yields a `Settings` equal to `Settings()` (observed).

The application has no dotenv loader; `from_env` reads only `os.environ`. The file is loaded by the runner:

```bash
cp .env.example .env                                # then edit your provider's variables
uv run --env-file .env uvicorn app.main:app --reload
```

Observed with uv 0.5.21: the inline `# ...` comments after values are stripped (`LLM_PROVIDER` arrives as `anthropic`, `LLM_MODEL` as the empty string), and a variable already set in the shell takes precedence over the file's value. `.env` itself is gitignored. Docker Compose does not read `.env.example`; by Compose's own rules a `.env` file in the project directory supplies values for the `${VAR:-default}` expressions in `docker-compose.yml`, so the same copied file can feed both a local `uv run` and `docker compose up` (Compose behavior, not exercised in this checkout).

### Logging

`app/main.py` configures logging once, at import, before `create_app` runs:

```python
logging.basicConfig(level=os.getenv("LOG_LEVEL", "INFO"), format="%(asctime)s %(levelname)s %(name)s %(message)s")
```

- `LOG_LEVEL` is a Python level name (`DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`). An unknown name raises `ValueError: Unknown level` at import, before the server binds (observed with `LOG_LEVEL=verbose`). Names are case-sensitive: `info` is rejected the same way (observed).
- Each module uses `logging.getLogger(__name__)`, so the `%(name)s` column names the module. Only three modules emit records: `app.main` (two lines), `app.chat` (four) and `app.memory` (one), all listed below. `app/brain.py` and `app/llm.py` define a `log` and never call it; the Neo4j driver logs under `neo4j.session`, and the SDKs' HTTP client under `httpx2`.
- **The chat line.** `ChatService.chat` ends every successful turn with one `INFO` record:

  ```python
        log.info("chat user=%s session=%s category=%s context_used=%s memory_updates=%d degraded=%s",
                 user_id, session_id, category, selection.context_used, updates, degraded)
  ```

  `category` is a `Category` (`StrEnum`), so it renders as `career`, `follow_up`, etc.; `context_used` renders as a Python list. Against the TDD §19 suggested field list: present are `user_id`, `session_id`, `query_category`, `context_used`, `memory_updates`, plus `degraded`; absent are `request_id`, `memories_retrieved`, `memories_selected`, `latency_ms`, `llm_provider` (recorded once per process in the `ready` line instead) and `error_type` (the warning lines below carry the exception text instead). Prompts, memory values and profile values are not logged, matching TDD §19 ("not full prompts by default") and README "Production path" ("prompts are not logged").
- **Warning lines** (all `WARNING`): `Neo4j unreachable at startup, serving degraded until it returns: ...` (`app/main.py`); `brain unavailable, answering from short-term context user=...` , `memory extraction failed, response still returned: ...`, `memory write failed, response still returned: ...` (`app/chat.py`). `app/memory.py` `validate` logs `dropping off-taxonomy candidate key=... category=... type=...` at `INFO` (the key, not the value).
- **Silenced Neo4j notifications.** `Neo4jBrain.__init__` passes `notifications_min_severity="OFF"` to the driver, with the comment "server hints about empty labels are noise on a fresh graph". On an empty database every `MATCH` on `:User`, `:Profile` or `:Memory` would otherwise come back with a server notification about the missing label; setting the minimum severity to OFF asks the server not to send any, so they never reach the driver's logging.
- **Driver retry warnings are not silenced.** During an outage the driver's own `neo4j.session` logger emits `WARNING Transaction failed and will be retried in <seconds>s (Couldn't connect to ...)` once per retry attempt (two or three per failed call in the observation recorded under "Failure modes"), before our `BrainUnavailable` warning. `notifications_min_severity` affects server notifications only, not these.

### `Dockerfile`, layer by layer

```dockerfile
FROM ghcr.io/astral-sh/uv:python3.12-bookworm-slim
WORKDIR /srv
ENV UV_COMPILE_BYTECODE=1 UV_LINK_MODE=copy
COPY pyproject.toml uv.lock ./
RUN uv sync --frozen --no-dev
COPY app ./app
EXPOSE 8000
CMD ["uv", "run", "--no-sync", "uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

|---|---|---|

- **`dev` group** (three): `pytest`, `pytest-asyncio`, `httpx`. `httpx` is what `tests/test_openai_llm.py` uses to build its fake server (`httpx.MockTransport` inside an `httpx.AsyncClient` passed as `http_client`). It is not what the SDKs use: in `uv.lock` both `anthropic` and `openai` depend on `httpx2`, and `starlette.testclient` imports `httpx2` first, falling back to `httpx` only if `httpx2` is absent, so `TestClient` also runs on `httpx2` in this environment. `uv sync` installs the group by default; the Dockerfile's `--no-dev` leaves it out.
- **`asyncio_mode = "auto"`**: every `async def test_*` runs under pytest-asyncio without a marker (CLAUDE.md). `tests/test_neo4j.py` and all of `tests/test_openai_llm.py` except `test_build_llm_selects_provider` are async; several tests in `tests/test_chat.py` and `tests/test_units.py` are too.
- **`testpaths = ["tests"]`**: a bare `uv run pytest` collects only `tests/`.
- **`pythonpath = ["."]`**: puts the repo root on `sys.path` so `from app.config import Settings` resolves. This is needed because the project is never installed: CLAUDE.md, "the project is not installed as a package".
- **No `[build-system]`**: uv treats the project as virtual. `uv.lock` records it as `source = { virtual = "." }`; `uv sync` creates the venv with dependencies only, and `app` is imported from the working directory in every mode (pytest via `pythonpath`, uvicorn via its cwd, the container via `WORKDIR /srv`).
- **Version `0.1.0`** is repeated in `FastAPI(title="AstroChat", version="0.1.0", ...)` in `app/main.py`; the two are not linked.

## Contracts and invariants

- **`Settings` is immutable and value-typed.** `@dataclass(frozen=True)`: assigning to a field raises `dataclasses.FrozenInstanceError` (observed), two instances with the same fields compare equal, and the object is hashable. No code in `app/` mutates or copies it.
- **The environment is read exactly once, at import of `app.main`.** `Settings.from_env()` runs inside `create_app()` at module level; `LOG_LEVEL` is read by `basicConfig` at the same import. There is no reload, no watch, no per-request lookup. A configuration change is a process restart.
- **Defaults are declared once.** The class attributes on `Settings` are the only place a default lives; `from_env` falls back to them; `.env.example`, README "Configuration" and the compose `${VAR:-default}` expressions mirror them by hand. No test asserts that the mirrors agree with the class.
- **`from_env` validates nothing except that three values parse as numbers.** Provider name and model presence are validated by `build_llm` / `OpenAICompatibleLLM.__init__` during lifespan startup, so a bad `LLM_PROVIDER` or a missing `LLM_MODEL` fails the process before it serves a request (CLAUDE.md: "`build_llm` raises at startup if it is missing"). `BRAIN` is not validated anywhere: only the exact string `memory` changes behavior.
- **Neo4j reachability is not a startup precondition.** `ensure_schema` failure is a warning, not an error (TDD §13.2, "Graceful degradation" in TDD §2). The process serves degraded until the database returns.
- **Injection beats environment.** Every argument of `create_app(brain=, llm=, settings=)` overrides what would otherwise come from `Settings`; `tests/conftest.py` passes all three. An injected `brain` or `llm` is used even if `settings` says otherwise (`brain or (...)`, `llm or build_llm(settings)`).
- **Consumers receive values, not `Settings`.** `SessionStore(limit: int)`, `ChatService(..., memory_limit: int, min_confidence: float)` and `Neo4jBrain(uri, user, password)` have no dependency on `app/config.py`; only `app/main.py` (to build it) and `app/llm.py` (for `build_llm`) import `Settings`.
- **Fixed ports and development credentials.** 8000 (app), 7474 (Neo4j HTTP), 7687 (bolt) are literal in `docker-compose.yml`, the Dockerfile `CMD` and README. The user/password pair `neo4j`/`password` is the development default in `Settings`, `.env.example`, `docker-compose.yml` (three places within it), `tests/test_neo4j.py`'s `os.getenv` fallbacks, and the README and CLAUDE.md commands. It is a development convenience, not a production value (TDD §20).
- **`uv.lock` is the build input.** `uv sync --frozen` in the image installs what the lock says and does not re-resolve; a `pyproject.toml` edit must be re-locked (`uv lock`, or a plain `uv sync` locally, which updates the lock) before it reaches the image.

## Failure modes and degraded behavior

Two timing facts shape the first rows. First, `import app.main` executes `app = create_app()` at module level, which calls `Settings.from_env()` and, a few lines earlier, `logging.basicConfig(level=os.getenv("LOG_LEVEL", "INFO"), ...)`; so a non-numeric `RECENT_LIMIT`, `MEMORY_LIMIT` or `MIN_CONFIDENCE`, or an unknown `LOG_LEVEL`, fails the import itself, and that includes `tests/conftest.py`'s `from app.main import create_app`, which makes the whole test suite fail at collection. Second, inside `lifespan` the order is `Neo4jBrain(...)` (driver constructed), `ensure_schema()` (network call, warning on failure), then `build_llm(settings)`; a `ValueError` from `build_llm` therefore happens after the driver exists and after the schema round trip, and because `await close()` sits after the `yield`, that driver is never closed on this path. Under uvicorn the process exits anyway; under `TestClient` the driver object is simply dropped.

| Condition | Detected | Behavior |
|---|---|---|
| `RECENT_LIMIT` or `MEMORY_LIMIT` not an integer, or set to the empty string (`VAR=`) | `Settings.from_env()` at import of `app.main` | `ValueError: invalid literal for int() with base 10: ...`. uvicorn never binds; a compose `app` container exits. `uv run pytest` fails at collection because `tests/conftest.py` imports `app.main` (observed) |
| `MIN_CONFIDENCE` not a float | same | `ValueError` from `float()` at import, with the same consequences for uvicorn and for the test suite |
| `LOG_LEVEL` not an uppercase Python level name | `logging.basicConfig` at import of `app.main` | `ValueError: Unknown level: '...'` (observed with `verbose` and with lowercase `info`); fails the import, so uvicorn and `uv run pytest` alike |
| `LLM_PROVIDER` not one of `anthropic`, `openai`, `mock` | `build_llm` in lifespan startup, after the brain was built and `ensure_schema` ran | `ValueError: unknown LLM_PROVIDER 'gemini'; use anthropic, openai or mock`; uvicorn logs the traceback and `Application startup failed. Exiting.` (observed). With `BRAIN=neo4j` the Neo4j driver constructed moments earlier is left unclosed (the `close()` call is after `yield`). Importing `app.main` still succeeds, so tests are unaffected |
| `LLM_PROVIDER=openai` with empty `LLM_MODEL` | `OpenAICompatibleLLM.__init__` in lifespan startup, same point as above | `ValueError: LLM_MODEL is required for LLM_PROVIDER=openai (model names are server-specific)`; startup fails as above, driver likewise unclosed. Pinned by `tests/test_openai_llm.py::test_build_llm_selects_provider` |
| `LLM_PROVIDER=anthropic` with no `ANTHROPIC_API_KEY` and no `ant auth` profile | first request, by the anthropic SDK | Startup succeeds: `anthropic.AsyncAnthropic()` constructs without credentials (observed with the key removed from the environment). | `OPENAI_BASE_URL` unreachable, or provider 5xx / 429 | first request | `LLMError` -> `503 LLM unavailable`; the turn is not appended to the session and nothing is written (TDD §13.3; `tests/test_chat.py::test_9_llm_failure_returns_503_and_mutates_nothing`) |
| Neo4j unreachable at startup (`BRAIN=neo4j`) | `ensure_schema` in lifespan | Warning `Neo4j unreachable at startup, serving degraded until it returns`; process starts. The constraints and index are not created until the process is restarted with Neo4j up (inferred; `ensure_schema` has one call site) |

| Wrong `NEO4J_PASSWORD` | `ensure_schema` in lifespan | `AuthError` is in `_CONNECTIVITY_ERRORS`, so it is translated to `BrainUnavailable` and takes the same degraded path as an outage. Only the exception text in the warning distinguishes them |

## Known limits and future work

**`ponytail:` markers in the covered files:** none. `app/config.py`, `.env.example`, `Dockerfile`, `docker-compose.yml`, `pyproject.toml` and `uv.lock` contain no deliberate-shortcut comments. Two markers elsewhere in `app/` bound how this layer can be deployed and are quoted verbatim:

- `app/session.py`, in the `SessionStore` docstring: `ponytail: process-local dict; swap for Redis when running more than one replica.`
- `app/brain.py`, in `Neo4jBrain.__init__`: `# ponytail: fixed timeout, no circuit breaker; add one when outages are long enough to matter per request.`

The remaining two markers in `app/` (`app/astrology.py`, tropical sun sign only; `app/context.py`, keyword classifier) belong to [Domain model](03-domain-model.md) and [Query understanding and context selection](04-query-understanding-and-context-selection.md).

Limits and the recorded path forward:

- **Single replica.** Short-term context is a process-local `deque`; a second `app` replica behind a load balancer would split a session's history. TDD §23 Phase 2: "Redis for session context"; README "Production path": "Redis session store". TDD §4.3 notes the swap makes the two `SessionStore` methods `async` and changes call sites in `app/chat.py` only.
- **Secrets as environment literals.** `docker-compose.yml` hardcodes `neo4j/password` and passes API keys from the invoking shell. TDD §20 names "a secret manager" as the alternative; README "Production path" lists credentials-from-environment as the current state. Neo4j is also published on the host with the default password, which is a development topology.
- **Observability gaps.** The chat log line lacks `request_id`, `latency_ms`, `memories_retrieved`/`memories_selected`, `llm_provider` and `error_type` from TDD §19; no metrics or tracing (TDD §23 Phase 2 "Metrics and tracing"; README "Production path": "structured logs already carry `request` fields ..., add tracing").
- **No health endpoint, `HEALTHCHECK`, `restart` policy or resource limits** for the `app` container; compose has a healthcheck only for Neo4j. The process runs as the image's default user (no `USER` instruction).
- **`ensure_schema` runs once.** If Neo4j is unreachable at startup, constraints and the `memory_lookup` index are never created for that process; the compose healthcheck avoids this in the one-command deployment, a bare `uv run` does not.
- **Unvalidated `BRAIN`; provider validation only at startup.** A typo in `BRAIN` silently means Neo4j. Moving both checks into `Settings.from_env` (or a `__post_init__`) would fail earlier with a variable name in the message; not done, no rationale recorded.
- **`LLM_EFFORT` empty is not omitted for Anthropic.** `AnthropicLLM.generate` always sends `output_config={"effort": self._effort}`; README "Configuration" and `.env.example` describe empty as "omit" for both providers. Either the code or the two documents should change; CLAUDE.md asks to keep `messages.create(..., output_config={"effort": ...})`, so the fix would be conditional inclusion like the OpenAI adapter's.
- **Compose does not pass `BRAIN`, `RECENT_LIMIT`, `MEMORY_LIMIT`, `MIN_CONFIDENCE` or `LOG_LEVEL`.** They are image defaults in that mode.
- **Mirrors are by hand.** `.env.example`, README "Configuration" and the compose defaults duplicate the `Settings` defaults with no test to keep them aligned.
- **Floating `neo4j:5` tag.** The tested pairing is driver 6.3.1 with Neo4j 5.26 (CLAUDE.md); a future `5.x` minor is pulled without a lock.
- **Interpreter drift.** The image fixes CPython 3.12; a local `uv run` picks any `>=3.12` (3.13.1 here). There is no `.python-version` file. The suite passes on both in this checkout.
- **No `.dockerignore`.** `COPY app ./app` copies whatever is under `app/`, including a host `__pycache__/`.
- **Synchronous memory update and no fallback provider** are not deployment concerns but bound what a deployment can promise: TDD §23 Phase 2 lists "Queue/background worker for memory extraction" and "LLM fallback provider"; README "Trade-offs" notes the queue "is a one-line move of the last block in `chat.py`".
